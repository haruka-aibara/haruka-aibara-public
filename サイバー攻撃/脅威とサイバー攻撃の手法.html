脅威とサイバー攻撃の手法を図で理解する

攻撃者は「調べる → 入る → 盗み見る → なりすます」の順に動く。手法名を並べて覚えるより、この流れのどこで効く話なのかを押さえたほうが早い。

脆弱性の種類に付く番号：CWE

脆弱性の報告を読むと CVE-2024-12345 と CWE-89 が並んで書かれている。番号が2種類あって紛らわしいが、指しているものが違う。

CVE は「どの製品の、どの脆弱性か」という個体の識別子。対して CWE（Common Weakness Enumeration）は「なぜ起きたか」という弱点の種類の識別子で、SQL インジェクションなら CWE-89、クロスサイトスクリプティングなら CWE-79 と決まっている。製品が違っても原因が同じなら CWE は同じ番号になる。

まず調べられる：ポートスキャン

攻撃はいきなり侵入から始まらない。最初にやられるのは「どのポートが開いていて、何が動いているか」の調査だ。TCP のハンドシェイクの応答の違いを利用して、開いているポートを外から判別する。

種類送るもの開いている閉じている特徴
TCP（コネクト）3ウェイハンドシェイクを完走接続成立RST結果は確実。接続ログに残る
SYN（ステルス／ハーフオープン）SYN のみ。応答が来たら RST で打ち切るSYN/ACKRST成立させないのでログに残りにくい
FINFIN フラグだけ応答なしRST「応答なし＝開」と逆読みする
NULLフラグを全部 0応答なしRST同上

FIN / NULL は相手の OS 次第で当てにならない。「開いているポートは無反応」は TCP の仕様どおりに実装した OS の挙動で、Windows など一部の OS は開いていても RST を返す。この場合スキャン結果は全ポート閉に見える。逆にこの反応の違いは、相手 OS の推測材料にもなる。

開いていること自体を隠す：ポートノッキングと SPA

SSH をインターネットに晒すと、スキャンされて総当たりログインが延々と来る。IP 制限をかけたいが、接続元が固定できない場面がある。そこで「普段はポートを閉じておき、正しい合図を出した相手にだけ開ける」やり方が出てくる。

侵入後にコードを実行させない：SSP・DEP・ASLR

バッファオーバーフローの狙いは「用意した領域からはみ出して書き込み、関数のリターンアドレスを自分のコードの番地に書き換える」こと。これに対する防御は1つではなく、成立条件を1つずつ潰す形で積み重なっている。

  • SSP（Stack Smashing Protector）：GCC の -fstack-protector 系オプション。リターンアドレスの手前に見張り用の値を置き、関数終了時に壊れていないか確認する。
  • automatic fortification：-D_FORTIFY_SOURCE=2 でコンパイルすると、strcpy や memcpy がコピー先サイズを検査する版に自動で差し替わる。ソースを書き換えずに境界チェックが入るのでこの名前で呼ばれる。
  • DEP（Data Execution Prevention）：Windows の呼び名。CPU の NX ビットを使い、スタックやヒープのページを実行不可にする。
  • ASLR：実行ファイル・ライブラリ・スタックの配置先を起動のたびにランダム化する。

いずれもビルド時オプションと OS 設定で決まる。自分たちでコンパイルして配布しているバイナリなら、有効になっているかを確認する価値がある。

通信を盗み見る：スニファとプロミスキャスモード

NIC は本来、自分宛（宛先 MAC が一致するもの）以外のフレームを捨てる。この破棄をやめて全部拾うのがプロミスキャスモードで、拾ったパケットを解析するツール（tcpdump や Wireshark）がスニファ。障害調査に必須の道具であり、盗聴の道具でもある。

無線 LAN：WEP / WPA / WPA2 と ESSID

無線は電波が届く範囲の全員に届くので、有線のスイッチのような分離がそもそも効かない。暗号化方式の世代がそのまま盗聴されるかどうかを決める。

方式暗号状況
WEPRC4 + 24 ビットの IVIV の使い回しから鍵を復元できる。通信量さえあれば数分で破れるため使ってはいけない
WPATKIP（RC4 のまま鍵を都度変える）WEP 世代の機器をファーム更新で救うための暫定策。現在は非推奨
WPA2CCMP（AES）長く実質標準。ただし個人モードは接続時のやりとりを捕まえるとオフラインで総当たりできるため、パスフレーズを長くする必要がある
WPA3SAEパスフレーズが弱くてもオフラインでの総当たりが成立しないよう作り直された世代

ESSID は無線ネットワークの名前。「ESSID ステルス（ビーコンに名前を載せない）にすれば安全」と言われがちだが、対策にはならない。接続済みの端末はその名前を平文で呼びかけながら電波を出すため、待っていれば拾える。MAC アドレスフィルタも同じ理由（MAC は平文で流れる）で回避される。無線で本当に効くのは暗号化方式の世代と、パスフレーズの長さだけだと考えたほうがいい。

認証を素通りする3つの手口

セッションフィクセーション

ログイン後の本人確認はセッション ID で行われる。ならば ID を盗むのではなく、攻撃者が知っている ID を利用者に使わせてしまえばいい——これがセッションフィクセーション（セッション固定攻撃）。

pass the hash

Windows の NTLM 認証は、パスワードそのものではなくパスワードのハッシュを鍵としてチャレンジレスポンスを行う。ここが弱点で、端末のメモリからハッシュを抜き出せれば、平文のパスワードを知らないままそのハッシュで他のサーバにログインできてしまう。ハッシュ化は「盗まれても平気」を意味しない、という代表例。

IP スプーフィング

送信元 IP アドレスを詐称してパケットを送る手口。IP アドレスは自己申告で、途中の経路は基本的に検証しない。用途は主に2つ。

  • 送信元 IP を根拠にしたアクセス制御の回避：「社内 IP なら許可」のような判定を騙す。
  • 反射・増幅型 DDoS：送信元を攻撃対象の IP に偽って DNS や NTP に小さな問い合わせを投げると、大きな応答が攻撃対象に集中する。攻撃者は自分の帯域以上の量を送りつけられる。

ただし TCP では詐称した IP に応答が返ってしまうためハンドシェイクを完走できず、そのまま通信を乗っ取るのは難しい。使われるのは UDP や、応答を必要としない攻撃が中心になる。対策はネットワーク側で行うもので、自分の管理下から出ていくパケットの送信元 IP を検査して、身に覚えのないものを落とす（BCP38 / 出口フィルタリング）。

ビジネス側への説明に置き換えると。ここまでの手法はどれも「侵入の前段」か「侵入後の横展開」で、単体の対策では止まらない。「入口を1枚厚くする」より「1台やられた後に全社に広がらない構造にする」ほうが投資対効果が高い——pass the hash とローカル管理者パスワードの使い回しは、その説明にそのまま使える題材。
