# ぶつかりそうな場所を、証拠付きで指す

## このスキルの立ち位置

見積もりが外れる原因は、たいてい「難しかったから」ではなく **「想定していなかった場所に触る羽目になったから」**。そしてそれは本人に聞いても出てこない。気づいていないから未知なのであって、自己申告できる未知は既に計画に入っている。

だから聞かずに、リポジトリの事実から拾う。履歴は「過去にどこで燃えたか」を知っている。

**やること**：ぶつかりそうな場所の**所在を指す**
**やらないこと**：その未知を**解消する**、詳細設計を決める、リスクを網羅的に列挙する

この区別が全て。所在を指すのは交渉の材料になる（「ここが重いので、この部分は別ストーリーに切りませんか」）。解消しに行くと、着手前に仕様書を書く作業になり、ストーリーから学習が抜けて、ただの指示待ち作業に変わる。

## 前倒ししてよい未知、してはいけない未知

未知を見つけて解消していく過程そのものが開発の中身なので、**着手前に全部潰すのは目的に反する**。INVEST でいう Negotiable（どう作るかはチームが決める余地）を殺すし、Valuable な学習も前倒しでは得られない。だから線を引く。

| 未知の種類 | 扱い | 理由 |
|---|---|---|
| 外にある未知（依存先の返答、受け入れ条件、権限、他チーム所有の領域） | **前倒しで動かす** | 自分たちの手で解けず、待ちを生む。早く投げるほど得 |
| ぶつかりそうな場所の所在 | **前倒しで指すだけ** | 交渉と分割の材料になる。潰す必要はない |
| 実装のやり方の未知 | **着手後に解く** | 机上で解くと精度が低く、Negotiable も失う。手を動かすのが最速 |

目安は **「スパイクを切るかどうかの判断がつく程度まで」**。それ以上調べるのは前倒しのしすぎ。

**未知をゼロにしようとしない。** 1〜2個残っているのが健全な状態で、ゼロなら Negotiable を削りすぎたか、そもそも単純な作業。

そして忘れてはいけないこと：**このスキルで未知の未知は消えない。** 出せるのは「過去に不安定だった場所」「予想より広い波及」「待ちが入る境界」まで。真に予想外のものは定義上出てこない。だから出力を安心材料として扱うと、かえって油断する。**予防ではなく早期検出**が目的で、見つけた場所は `story-breakdown` の基準線（いつ確認するか）に接続して初めて意味を持つ。

## 手順

### 1. 触る範囲の当たりをつける

ストーリーの記述から、変更が入りそうなファイル・ディレクトリを特定する。分からなければ、キーワードで grep して起点を見つける。この段階では粗くてよい。

### 2. 履歴から証拠を集める

同梱のスクリプトを使う。変更回数・修正系コミットの割合・著者の集中度・同時に変更されがちなファイルをまとめて出す。

```bash
python3 .claude/skills/collision-scan/scripts/hotspots.py --since 1.year <触りそうなパス...>
```

読み方：

- **修正系コミットの割合が高い**：繰り返し燃えてきた場所。次も燃える確率が高い
- **同時変更の相手（co-change）**：ここが一番価値がある。「A を触ると B も直す羽目になる」は人の記憶に残っていないことが多い。5割を超える相手は、実質そのファイルの一部だと思ってよい
- **著者が1人**：技術的な難しさではなく、**待ち時間**の原因になる

### 3. 波及を実測する

変更予定の関数・クラス・設定キーの参照元を実際に数える。想定より多ければ、それ自体がぶつかりどころ。「たぶん影響は狭い」を数字で潰す。

### 4. 境界を確認する

跨ぐと自分たちだけでは終わらなくなる境界を見る。外部 API、他チーム所有のコード、DB スキーマ、認証・権限、インフラ設定、ライセンス。跨ぐなら、それは前倒しで動かす未知（上の表の1行目）。

### 5. テストの薄さを見る

変更対象に対応するテストがあるか。無ければ「壊れても気づけない場所」で、ぶつかったときの発覚が遅れる。

## 出力

**3〜5件に絞る。** 件数を増やすほど読まれなくなり、最後には全部無視される。証拠のない「〜かもしれない」は1件も入れない。

```markdown
## ぶつかりそうな場所

### 1. <場所> — <一言で何が起きるか>
- 証拠：<履歴・参照数・著者数など、確認できる事実>
- ぶつかると：<起きること。手戻り／待ち／範囲拡大のどれか>
- 早く気づくには：<いつ何を確認すれば分かるか>

### 2. ...

## 前倒しで動かすもの（自分たちで解けない未知）
- <依存先への確認事項。いつ投げるか>

## 見ていない範囲
- <履歴が浅い・触っていない領域など、このスキャンで拾えていない場所>
```

最後の「見ていない範囲」を省かない。**このスキャンで出なかった＝安全ではない**ことを、読む人に伝えるため。
